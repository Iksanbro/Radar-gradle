# Задача: стыковочный контроллер (Minecraft, radar_fcs)

> **Сделано в 1.1-Test** — итог в `docs/dev/features.md`, п. 43.

> Мод для видеоигры **Minecraft** 1.21.1 (NeoForge). Задача — новый игровой блок для автоматической стыковки
> летающих построек (кораблей Sable / Create Aeronautics) в игровом мире. Контекст проекта — `radar_fcs/CLAUDE.md`.

## Просьба пользователя (своими словами)
Добавить блок «Стыковочный контроллер», доступный только при установленном Create: Flight Control (как мост
автопилота `compat/flight/FlightBridge*`). У блока две роли:

- **Порт** — стоит у стыковочного порта Create Aeronautics (на земле, станции, другом корабле) и подключается к
  радарной сети через радарный линк. Портов в сети может быть сколько угодно.
- **Штекер** — стоит на корабле у его стыковочного порта и связан с мостом автопилота этого корабля
  (через ту же радарную сеть).

У каждого контроллера — **числовой номер**. Штекер настраивается на номер, и корабль летит к порту с этим номером.
Один номер может быть сразу у нескольких портов (например, у двух) — тогда штекер выбирает подходящий
(ближайший свободный).

**Когда лететь на стыковку** задаётся в настройках моста автопилота:
- при отсутствии цели (назначенной цели нет — корабль возвращается на стыковку);
- при активном редстоун-сигнале на мосту;
- (и, по смыслу, «выключено» — как сейчас).

Корабль со штекером подлетает так, чтобы штекер совпал с портом: дальний подход — как сейчас летает мост,
ближний — медленно и точно, с выравниванием курса; дальше соединяет сам порт Create Aeronautics.

## Порядок работы
1. Изучить, как устроен стыковочный порт Create Aeronautics и есть ли у него API для «подлетел — соединись»
   (jar в `run/mods` или в кэше Gradle; **код чужих модов не копировать**, только вызывать их API).
   Перед реализацией кратко показать пользователю план и спросить о спорных местах:
   один блок с переключателем роли или два разных блока; что делать, если все порты с номером заняты;
   нужна ли новая версия мода (без спроса версию не менять).
2. Блок, block entity, экран настроек (номер, роль), регистрация только с Flight Control (рецепт, лут, теги —
   с условиями загрузки, как у моста), подключение через `link/` (`LinkKind`), ru/en переводы, текстура
   (`devtools/textures.py`, стиль остальных блоков).
3. Настройка «когда стыковаться» в мосту (`FlightBridgeBlockEntity`, `client/AutopilotScreen`), полёт к порту —
   через ту же навигационную аренду Flight Control, что и сейчас.
4. Игровые тесты по образцу `FlightGameTests` (подлёт к порту по номеру, выбор из двух портов с одним номером,
   оба триггера — нет цели и редстоун), `./gradlew build`, jar в `release/`, ссылка на скачивание.
5. Записать итог в `docs/dev/features.md` (новый пункт в конце) и при необходимости поправить `CLAUDE.md`.
